# Recycling — Module 1: Waste Purchases

Implemented locally on 25 October 2026. Four selectable modules are shown; only Module 1 has a defined workflow. Modules 2–4 remain explicitly pending the user's process descriptions. Module selection is retained in the URL. Switching modules preserves the Module 1 form while this page remains mounted. Earlier production-waste/granules reference-view source is retained in RecyclingReferenceViews.tsx; existing records and APIs are unchanged.

Module 1 follows the supplied material purchase workbook: date, material, supplier, quantity, selectable kg/pcs, unit price, currency and notes. Workbook material names are starter choices, not a closed catalog. Authorized staff can add a new material independently of a purchase. The material is saved to shared backend records and remains available across months/accounts. Names must be unique without regard to case. Existing names cannot be renamed/deleted through this module, preserving historical purchase identity.

Purchases and the custom catalog use versioned `recycling-purchases` and `recycling-materials` shared entries. Accepted saves retain authenticated actor, server timestamp and full prior content in Entry History. UI closes a save only after server confirmation. Conflicts/failures remain visible in the existing recovery banner. Shared collection limits currently apply: 2 MB per key and 10,000 rows. No historical workbook transactions were imported.

Recycling Operator, Store Keeper, Accounts and Admin may enter materials/purchases when they also possess the backend change capability. Production/Project Managers have read access. Migration erp.0020 grants the recycling role the shared-entry change capability; each key still enforces its own role scope. Demo accounts cannot save.

Monthly summaries are calculated by the backend from active entries' actual dates, grouped by material + unit + currency. Line amounts use decimal quantity × unit price, rounded half up to two decimal places, before summing. Quantity accepts three decimal places; unit price accepts four. Different units and currencies are never combined into one total. Zero-price receipts are permitted. Supplier is required for new entries.

Corrections require a reason; voiding keeps the entry visible, excludes it from totals, and prevents further changes. Physical deletion is rejected. These are purchase records, not payments, stock postings or manufactured granules receipts.

`GET /api/recycling/purchases/report/?month=YYYY-MM` returns the authoritative summary and details. `export=xlsx` produces native Excel with summary and detail worksheets; text is stored literally to prevent formula execution. `export=pdf` produces a paginated report. Both exports include all materials for the selected month and retain voided detail with status. The on-screen material filter narrows the detail register only.
